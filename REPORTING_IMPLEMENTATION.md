# Report document implementation

## Architecture

The summary API validates filters with `ReportDataService`, calls the existing `MealSelectionModel::getSummary()` without changing its SQL or calculation rules, and formats one document snapshot. The snapshot is bound to the authenticated session, retained for two hours (latest five reports), and shared by Print and Export PDF. Applying filters refreshes the snapshot; an already-open preview exports its original snapshot. Expired previews show a useful error.

`ReportRenderer::html()` renders `frontend/reports/partials/document.php`. The dedicated print route and TCPDF 6.10.0 both consume that HTML and the same base CSS. Only browser page styling and TCPDF's per-page footer are renderer-specific. Section titles and column headers repeat on continuation pages. Charts stay on the dashboard; exports use full aggregate tables. Existing top-meal and top-staff rankings remain limited to 10 and are explicitly labelled.

All routes enforce the existing administrator permission. Date ranges, shift values and report types are validated; values are escaped; errors are logged server-side and user-facing messages do not expose internals. Authenticated names are used when present, with the existing login session's username as fallback. Generation time uses Africa/Accra. No database migrations or unrelated operational modules were changed.

## Print and PDF behavior

Print Report opens a separate document tab. Its toolbar disappears in print; navigation, filters, dashboard cards and chart controls are absent from the document itself. A4 portrait suits all existing 2- and 3-column reports. Long descriptions wrap, numeric columns align right, and empty reports have a compact message.

PDF exports are real searchable documents generated by the installed TCPDF engine, using the same metadata, rows, summaries and totals as Print. Filenames identify the report, period type and date boundaries. Browser and PDF pagination can differ with fonts/printer settings; PDF page numbers are supplied by TCPDF. Browser headers/footers remain controlled by the print dialog.

The report routes and dashboard dependencies work offline. Bootstrap and Chart.js versions match those previously loaded from CDNs. Unused DataTables assets were removed only from the reports page; no DataTables instance was initialized there. Other application pages retain their existing dependencies.

The official Concentrix white wordmark is stored locally against its dark brand background. Source: https://www.concentrix.com/wp-content/uploads/2026/04/concentrix_logo-1.webp . Its aspect ratio is preserved. Set `REPORT_COMPANY_LOGO` to another approved PNG/JPEG path relative to `frontend` when needed; missing/unreadable files fall back to the company name. No logo or font is fetched remotely at runtime.

## Running the checks

From the repository root:

```powershell
php tests/ReportTest.php --database
php backend/vendor/phpunit/phpunit/phpunit -c tests/phpunit.xml
php tests/CommandTest.php
node tests/node/sheet.test.js
```

For browser checks, install/provide Playwright, run the fixture test, then `php tests/prepare-report-session.php`. Start a separate PHP development server at `127.0.0.1:8091` with `APP_BASE_PATH=/` and an **absolute** `session.save_path` pointing to this repository's `storage/reports-qa/sessions`. Do not use production session storage. Set `REPORT_PLAYWRIGHT_MODULE` to a Playwright module path if it is not on Node's module resolution path, and optionally set `REPORT_BROWSER_EXECUTABLE` to Chromium/Edge. Run `node tests/report-browser.cjs`, followed by `python tests/verify-report-pdfs.py` (requires pypdf). Stop the isolated server afterward.

Generated fixtures and screenshots live under ignored `storage/reports-qa`, which denies Apache access. They are QA artifacts, not application report routes.

## Report action follow-up fix

Report assets now use versioned, application-base-aware URLs, including on Apache's `/reports` shortcut routes. The Print/PDF buttons have native form actions as a fallback; JavaScript export preparation fetches its own report context instead of depending on `loadSummary()` from the charts script. A blocked preview popup falls back to the same tab. The preview's PDF action also has a native form fallback.

Actual Apache regression checks cover canonical and shortcut routes, missing chart scripts, missing action scripts, and JavaScript-disabled native forms. Each scenario checks Print preview and PDF exports from both dashboard and preview, while retaining the selected dates.

Run these focused checks with Apache running and Playwright configured as above:

```powershell
php tests/ReportActionsSession.php
node tests/report-actions-browser.cjs
php tests/ReportActionsSession.php cleanup
```

The helper creates a random temporary QA session in the CLI PHP session directory (which must match Apache's), without creating a database user or changing existing sessions. Always run cleanup, including after failed tests. `REPORT_TEST_BASE` may override the default `http://localhost/cnx_canteen` URL.

## Simplified report metadata and page footers

The document card now contains Generated By, User Role, Report Ref and Shift. Report Name, Report Period, generated date/time, Report Type and Data Scope are omitted from the card. The confidentiality statement has been removed from both outputs.

The former text block below the report tables has been removed. TCPDF and the print document now use a page footer containing the company/system identity, the snapshot's generation timestamp and page numbering. The browser uses CSS paged-media margin boxes in current Chrome/Edge, while the screen preview places its footer at the bottom of the document. Report titles, periods, table contents and totals remain unchanged.
